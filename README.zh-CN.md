**收藏值得花时间理解的内容，用飞书整理与回顾。**

NewsBridge 是一个开源 Chrome 插件，帮助用户收藏文章、视频等需要投入时间理解的内容，并利用飞书多维表格管理素材、类别、阅读状态和笔记。

先收藏，有时间再阅读或观看，并记录自己的理解。通过多维表格把相关素材放在一起回顾，让分散的收藏逐步形成相互关联的知识。

## 功能

- **收藏：** 从 Chrome 保存文章、视频页面或其他资料的标题和链接。
- **整理：** 用下方八个字段，在飞书多维表格中管理内容、类别、推荐指数和笔记。
- **跟进进度：** 在扩展与多维表格之间同步阅读状态；对视频，同一字段表示观看进度，由用户手动更新。
- **回顾理解：** 通过飞书视图聚合相关素材，在笔记中记录自己的理解。
- 收藏后、Chrome 启动时、手动操作时同步；启用同步后，Chrome 运行期间每 15 分钟同步一次。

收藏视频保存的是页面标题和链接，不包含视频下载、音频转写或自动播放进度追踪。

## 可选的每日提醒

配置飞书会话后，服务器按设定时区（默认 Asia/Shanghai）在每天上午 10 点发送未读素材提醒。提醒用于辅助阅读；不配置提醒会话，也可以收藏和管理表格。

- 以登录用户的身份，向配置好的飞书 `chat_id` 发送标题链接、类别、摘要和笔记。
- 每次发送前重新读取飞书状态，排除已读、已沉淀、已归档、已删除或没有链接的素材。
- 单独记录发送结果；发送成功不会把文章标为已读，第二天仍未读的素材会再次提醒。

提醒包含未读且具有 HTTP(S) 链接的素材，按收藏时间从早到晚排列。不设数量门槛，只有 1 条也会发送；没有未读素材时不发送。素材较多时，每条消息最多包含 20 条，剩余素材也会发送。消息支持中文和英文。

每个账号、表格和会话每天完成一次推送，同一天不会重复；当次推送结束后新增的素材留到第二天。收藏和手动同步只更新表格，不触发阅读提醒。

自动发送要求服务器及其定时任务运行，并且飞书授权有效。已同步到多维表格的素材无需打开 Chrome 即可提醒。若错过运行时间，服务器在当天 10 点后的下一次检查时尝试补发，不追发之前错过的日期。CLI 授权无法自动续期时，需在配置的工作目录中重新授权。

## 多维表格

请使用以下准确的字段名称，扩展按这些名称读取数据。

| 标题 | 链接 | 内容 | 类别 | 阅读状态 | 推荐指数 | 笔记 | 时间 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 文本，主字段 | 超链接 | 文本摘要与回顾问题 | 单选 | 单选 | 数字，1–5 | 文本，个人理解 | 日期 |

也兼容文本类型的链接、多选类型的类别，以及评分类型的推荐指数。

建议类别：**Builder Insights**、**Tech Radar**、**Project Watch**、**Try This**、**待分类**。

阅读状态：**待阅读、阅读中、已读、已沉淀、归档**。前两项视为未读；也识别“已归档”。

已有素材的内容、笔记和状态以飞书为准。新收藏只保存标题和链接，类别为“待分类”；扩展不会自动抓取正文、生成摘要或评分。笔记在多维表格中编辑；阅读状态可在飞书或扩展中修改。飞书中已删除的关联记录不会被重新创建。

## 开始使用

配置文件、参数填写和部署顺序见 [服务器配置指南](SETUP.md)。

需要 Chrome 106 或以上版本，以及能编辑目标多维表格的飞书账号。连接服务运行在服务器上，需要 Node.js 22 或以上版本和已授权的 [官方 lark-cli](https://github.com/larksuite/cli)。

1. 导入下方的 Daily Briefing 模板，检查八个字段的类型和阅读状态选项。
2. 参考 [服务器配置示例](server/server.config.example.json)、[Nginx 模板](deploy/nginx/) 和 [systemd 服务与定时器模板](deploy/systemd/) 配置自己的 HTTPS 服务。设置目标表格、授权账号和扩展 ID；会话 ID 可留空。
3. 执行 `node scripts/configure-server.mjs https://your-server.example`，指定唯一允许访问的服务器域名；服务器和 Nginx 配置使用同一域名。仓库中的域名是部署示例，不是公共服务。
4. 在 `chrome://extensions` 开启开发者模式，加载本项目文件夹，将生成的扩展 ID 填入服务器配置。
5. 在扩展 Settings 中填写服务访问密钥，检查连接并同步资料库。飞书凭证保留在服务器上。

收藏和手动同步只更新表格。需要未读提醒时，再启用服务器的每日定时任务；首次运行若已过当天 10 点，可以发送当天提醒。

## 连接方式

连接路径为 **Chrome → 你配置的 HTTPS 服务 → 已授权的 lark-cli → 飞书云端 API**。扩展只允许访问配置好的服务器域名；服务限定可操作的表格、会话和字段。

当前部署模板适用于 Ubuntu 24.04 服务器。Nginx 接收 HTTPS 请求，转发给只监听服务器回环地址的服务。用户电脑不运行监听服务。NewsBridge 不读取飞书客户端登录信息或网页 Cookie，需要单独完成 CLI 授权。

## Daily Briefing 模板

模板包含 10 条示例素材，已填入来源链接、摘要、类别和建议评分；个人笔记留空，状态为待阅读。时间表示收藏日期，不是发布日期；补充阅读和建议实验已作标注。

- [Excel 模板](templates/Daily-Briefing-飞书阅读模板.xlsx)
- [CSV 导入文件](templates/Daily-Briefing-飞书阅读模板.csv)

这些内容是初始示例，不是自动更新的新闻流。建议在飞书中建立按类别分组、按阅读状态筛选的视图，把相关素材放在一起回顾，并在“笔记”中记录共同结论和自己的验证。

## 数据与发送记录

收藏、语言设置、表格缓存和服务访问密钥保存在当前 Chrome 配置中。飞书凭证由服务器上的 lark-cli 管理，扩展不保存飞书 App Secret、访问令牌或刷新令牌。发送记录保存在服务器配置的私有状态目录内的 `notification-state.json`。凭证和发送记录不应上传 Git，请按私有资料保管和备份。

发送记录按应用、账号、表格和会话隔离。共用同一状态目录的服务器请求与每日任务通过进程锁串行执行，Chrome 重启后仍保留发送结果。不同服务器状态目录不共享记录，建议一个发送目标只配置一个发送端。

发送结果不确定时，一小时内使用原请求 UUID 重试。超过窗口或批次状态、链接变化时暂停，先核实目标会话，再在 Settings 确认“已送达”或“未送达”。不要清空整个发送记录。详见 [恢复说明](docs/ARCHITECTURE.md#delivery-recovery)。

项目不包含统计追踪、日历预约或 Agent 连接器。[相关项目](docs/RELATED-PROJECTS.md) 列出了原作者独立的飞书消息桥接项目。CLI 自身的安全与数据处理说明见 [安全文档](SECURITY.md)。

## 测试与安全

```sh
npm test
npm run security
```

测试覆盖八字段映射、双向阅读状态、每日调度、同日补发、次日提醒、发送重试、账号校验、私有文件、并发锁、HTTPS API 鉴权和请求限制。飞书响应使用模拟数据，测试不会登录或发送真实消息；本地测试不能验证实际部署环境。

安全措施包括精确扩展来源限制、固定 CLI 路径及工作目录、限定表格与会话、仅允许阅读字段操作、禁止任意命令、私有发送记录，以及危险链接和原始错误信息拦截。防护范围与局限见 [SECURITY.md](SECURITY.md) 和 [检查报告](docs/SECURITY-AUDIT.md)。结构说明见 [架构文档](docs/ARCHITECTURE.md)。

扩展无需构建步骤或 npm 运行时依赖。服务器需要 Node.js 和已授权的 lark-cli；部署模板由使用者配置和安装。新增托管平台或其他架构依赖前，应遵守 [项目协作规则](AGENTS.md) 并先取得明确选择。
