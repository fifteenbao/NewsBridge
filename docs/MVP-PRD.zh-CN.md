# NewsBridge MVP PRD：从收藏到一次有结果的阅读对话

[English](MVP-PRD.md) | 简体中文

文档修订：草案 0.1 · 2026-10-15。用于讨论产品方向，不代表发布版本、已实现能力或技术选型。现有版本的功能以 README 为准。

## 1. 产品假设

用户已经收藏了值得阅读或观看的内容，但缺少开始的契机，也缺少将阅读变成理解和应用的反馈。

NewsBridge 主动发起一次短阅读对话：给出具体阅读起点，在用户回应后提供有来源的反馈、解释或应用挑战，推动这次阅读产生一个明确结果。

**核心假设：相比只收到未读链接，收到具体阅读任务并能获得回应后的反馈，更容易让用户完成一次有价值的阅读。** 这是待验证的假设。

## 2. 目标用户与场景

首批用户：经常收藏长文章或视频、主要使用 Chrome 和飞书、愿意偶尔花约 5–10 分钟深入处理一份内容的人。

典型场景：收到一条飞书邀请，打开收藏内容中指定的一节，读完后表达理解或疑问；获得反馈并选择修订、尝试应用或结束。

本轮不解决收藏工具之间的全面整合，也不要求用户更换原有收藏工具。

## 3. 一次会话要交付什么

至少完成以下一种结果，由用户确认是否有帮助：

- 一个疑问得到有依据的解释；无法回答时明确缺少什么。
- 一个理解得到检验，用户确认或修订自己的判断。
- 一个观点转化为用户愿意尝试的具体行动。

保存笔记、发送摘要、标记已读本身不计为上述结果。AI 反馈不等于事实验证，也不代表测量了用户的认知能力。

## 4. 核心流程与最小功能

| 环节 | MVP 行为 | 完成条件 |
|---|---|---|
| 素材进入 | 复用现有 Chrome 收藏入口，或手动提交链接和一段摘录；标题自动获取，标签与收藏原因可选 | 素材已保存，并显示可用内容范围 |
| 准备阅读 | 从未处理素材选取一份；基于实际取得的正文或用户摘录，给出阅读位置和一个问题 | 用户可以定位原文，并知道本次要处理什么 |
| 主动邀请 | 在用户设定的时间通过飞书发送邀请；每天最多一次，包含开始、稍后、跳过、暂停入口 | 送达结果可追踪；未回复不连续催促 |
| 用户回应 | 支持自由文字，并提供“解释一下 / 检验理解 / 试着应用 / 结束”意图选择 | 回复关联到明确的素材与会话 |
| AI 反馈 | 根据意图提供一次有出处的回应，最多附一个后续问题 | 用户能检查依据，并可纠正或质疑反馈 |
| 收束 | 默认在 1–3 轮内邀请结束；用户可继续或随时退出 | 展示本次结论、未解决问题及可选下一步，由用户确认或修改 |
| 再次接触 | 用户主动选择回顾时间或行动跟进时间 | 到期回到上次具体问题；不自动生成持续任务 |

5–10 分钟与 1–3 轮是体验设计起点，不是完成要求或效果承诺。

### 回复之后的处理规则

| 用户意图 | 系统回应 | 例子 |
|---|---|---|
| 解释一下 | 定位相关段落，解释概念与适用条件；信息不足时说明 | “这里的成本是编码成本，还是整个项目成本？” |
| 检验理解 | 对照原文指出一致、遗漏或不受支持之处；可给一个新情境 | “在需求频繁变化的项目里，这个结论还成立吗？” |
| 试着应用 | 先确认用户目标和约束，再建议一个小行动，由用户决定是否采用 | “对下一个任务记录开发与返工耗时，再比较。” |
| 不同意 / 提问 | 接受质疑，展示依据，必要时修正 AI 回应；允许暂不确定 | 原文中的主张不被直接当作已证实事实 |
| 结束 / 跳过 | 立即停止追问并同步状态 | 不把结束自动标为“理解正确”或“已读” |

### 完整交互示例

1. 飞书邀请：“你收藏的文章中，‘开发速度与交付速度’这一节约需阅读 5 分钟。作者认为两者为何不同？”附原文链接及具体段落位置。
2. 用户：“因为需求没想清楚。”
3. AI：“这对应作者讨论的返工成本。作者还提出测试与集成成本（附原文位置）。如果需求已经清楚，编码变快是否一定让交付同比变快？”
4. 用户：“不一定，测试可能仍是瓶颈。”
5. AI 提议保存修订，并让用户选择结束，或为自己的一个任务设计耗时记录。用户确认后才建立跟进。

示例为虚构交互，实际反馈必须有对应材料支持。

## 5. 内容与质量边界

- 优先验证文章场景；视频仅在有用户提供的字幕或可合法获取的文本时参与内容分析，不假设已有转写能力。
- 只有标题和链接时，不生成伪装成全文审阅的反馈；请求用户提供摘录，或允许仅保存素材。
- 明确显示分析范围：全文、摘录或字幕片段。推断阅读耗时需标为估计。
- 反馈区分原文观点、AI 推断、用户理解；来源至少保留链接与可定位段落，视频保留可用的时间点。
- AI 问题与反馈必须能回到材料检查。用户可报告无依据、误解或错误归因。
- 默认只分析用户选定的素材；额外联网检索需另行说明范围，不作为 MVP 前提。
- 不用统一分数评价智力、创造力或认知改善。认知训练先体现为自我解释、应用与修订；六周实验不整体移入产品。

## 6. 状态与数据

分别保存四组状态，避免相互替代：

- 素材：未读 / 已读 / 跳过，由用户确认。
- 消息：待发送 / 已发送 / 发送失败 / 结果不确定。
- 会话：待回应 / 进行中 / 已结束；暂停不强迫完成。
- 跟进：未设定 / 待回顾 / 已完成 / 已取消。

最小数据包括素材来源与可用内容、阅读位置、邀请、用户原始回答、AI 反馈及依据、用户修订、可选跟进时间。修订不覆盖原始回答；保留这些记录是为了继续对话和回顾。

讨论中的职责分配：Chrome 收集；服务端持久化、定时任务及 AI 调用；飞书负责邀请和回复。飞书 / Google 表格不作为新方向的必需组件，现有支持是否保留待决定。

此处仅定义职责，不选定服务器、模型供应商、数据库、费用或凭证方案。所有新依赖在实现前另行确认。实际调用 AI 前须告知用户哪些素材和回复会发往哪里，并支持暂停、导出与删除。

## 7. MVP 范围

**包含：** 单用户阅读流程、单篇文章、用户设定的每日邀请、飞书文字回复、三种反馈意图、来源定位、状态同步、可选一次回顾、暂停及数据导出删除。

**暂不包含：** 新建通用收藏管理器、多平台收藏全量同步、全文阅读器、视频下载或转写、多素材自动知识图谱、自动执行外部行动、日历预约、脑力游戏、完整六周训练计划。

跨素材联系可以人工提供作探索，但不作为第一版依赖。

## 8. 验证计划

先用小样本人工协助运行，不先投入新的部署与完整 AI 自动化。建议起点：3–5 人、每人 6 次邀请，在同一用户内交替使用“仅链接邀请”和“具体阅读任务＋反馈”，尽量匹配主题兴趣、材料难度与时间投入。规模和周期可调整，结果仅作为方向性证据。

观察：

| 指标 | 定义 |
|---|---|
| 开始比例 | 已确认送达的邀请中，用户明确开始阅读的比例 |
| 有结果会话比例（主要指标） | 已确认送达的邀请中，用户确认获得第 3 节任一结果的比例；两组均用同样方式询问 |
| 反馈帮助度 | 接受 AI 反馈的用户是否认为它推进了理解，以及具体推进之处 |
| 自愿继续 | 用户是否主动选择再次阅读、回顾或下一次邀请 |
| 负担与错误 | 跳过、暂停原因；单次耗时；无依据反馈和错误归因 |

不以消息送达、摘要数量、笔记字数或连续打卡作为核心成功指标。初次实验不声称因果效果、知识长期保持或广泛认知提升。

进入开发下一阶段的条件：多位参与者反复指出回复后的反馈产生了具体价值，愿意继续使用，且来源质量与打扰程度可接受。若只想要摘要，优先验证摘要产品；若反馈没有帮助，先调整对话而非扩展平台。具体量化门槛在试验开始前约定。

## 9. 本轮需要打磨的决定

1. 核心承诺应优先是“更容易开始阅读”，还是“读后获得有用反馈”？当前草案偏向后者，同时保留主动邀请。
2. 第一批用户最想要解释、理解挑战还是实际应用？首轮应观察自然选择，不强制训练。
3. 首次邀请直接提供阅读任务，还是先让用户选择今天有多少时间？
4. 哪些内容及回复可以进入 AI，采用什么服务、保留多久？
5. 现有表格支持保留、降为导出，还是删除？应在验证后决定。

本 PRD 不触发代码重构、表格删除、部署、真实消息发送或版本升级。
