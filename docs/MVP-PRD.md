# ReadFlow MVP PRD

文档修订 0.4 · 2026-10-23；软件版本 V0.4.1。本文确认数据库主库、双入口收藏、可选飞书互动、手动导出边界。

## 1. 产品目标

把已经收藏的内容重新带回注意力中，降低开始阅读的门槛。后续通过有来源、贴合用户意图的 AI 反馈，解决疑问、检验理解或确定行动。收藏数量、摘要字数、消息送达都不能单独代表消化。

## 2. 职责与数据归属

| 部分 | 职责 |
| --- | --- |
| Chrome | 随手收藏标题／链接，选填标签与备注，本机待同步队列、轻量未读列表与状态操作 |
| ReadFlow 服务 | SQLite 唯一主库、鉴权、去重、任务、发送记录和导出 |
| 飞书私聊 | 可选链接入口、落库确认、阅读邀请与已读／稍后／跳过操作 |
| 飞书多维表格 | 用户点击后才更新的单向导出副本；不回写主库 |
| CSV | 用户主动下载的数据库内容快照，不含配对与任务状态 |
| 用户自己的 agent | 可选配置助手，不是产品内的阅读 AI，也不是日常运行依赖 |

SQLite 在现有服务单机私有目录运行，不新增数据库账号或托管平台。其他表格提供方暂不支持。新增外部服务、费用、模型或托管方案须另行确认。

## 3. 已落地范围

- 两种入口共用数据库，按 URL 去重；新收藏不会覆盖已有状态和笔记。标签／备注仅显式修改时更新；编辑 UUID 防止旧请求重放覆盖新值。
- 首次弹窗显示连接指引，可明确选择本机收藏；已配置后服务器暂时断网也能收藏。未入库内容显示“本机待同步”，不冒充备份成功。
- 普通用户只填 HTTPS 服务地址并配对，不再填写主库表格链接。扩展 ID、指纹、部署和发送排障归入配置／高级流程。
- 飞书事件先持久化，再由既有任务落库；落库后发送新增／已存在确认。失败保持可重试，送达不确定时保留请求 UUID。
- 阅读卡片提供打开、已读、稍后 24 小时、跳过；按钮验证用户、会话、已发送消息与记录绑定。状态写入数据库，Chrome 下次同步可见。打开原文不自动标已读。
- 每日提醒的时间、时区、语言和开关可配置；调度属于服务端。读取数据库，绝不依赖导出表。
- 手动“同步到飞书”先上传待同步内容，再单向按 URL 新增／更新导出表；覆盖十个管理列，不删除其他行、不读取表格修改回主库。
- 手动 CSV 导出全部数据库记录，处理中文、换行、引号及表格公式注入；CSV 不等同完整数据库备份。

当前不抓文章正文、不下载或转写视频、不通过标题假装读过全文。飞书入口标题暂为 URL。未实现统一删除、笔记编辑界面、多机部署、自动保留清理与 AI Review。

## 4. AI Review 最小实验（后续）

1. 取得真实正文或用户摘录后，基于片段和来源发起低门槛阅读邀请。
2. 用户选择解释、讨论、应用、稍后或跳过，自由回复与快捷入口并存；无回复不连续催促。
3. 根据用户意图提供一次有依据的反馈：解释概念、检查论据与遗漏、或针对实际约束提出小尝试。
4. 由用户确认疑问是否解决、判断是否修订、是否愿意行动或后续跟进。保存纪要只是辅助，不独立算成功。

后续讨论需区分用户原话、AI 推断和用户确认结论；“讨论过”不等于“已读”。文章正文、字幕获取、SSRF 防护、模型与费用、数据去向和删除边界在启用前单独设计。

## 5. 验收

- 不配置飞书凭证也能完成数据库收藏、状态修改和 CSV。
- 重复收藏、重启与响应丢失不会产生重复记录或重复应用旧编辑。
- 自动同步、提醒、健康检查均不写多维表格；只有明确导出操作写表。
- 飞书表格编辑不改变数据库；部分导出失败可在重新列出目标后安全重试。
- 卡片伪造、越权用户、未知消息与重复事件不错误改变阅读状态。
- 服务故障保留本机待同步内容；首次未配置与临时离线有不同提示。
- 中文文档、设置与实际运行边界一致。模拟验证不冒充真实飞书验证。

后续可用 5–10 名用户、两周的小实验对比“链接提醒”和“片段＋针对回应反馈”，重点观察具体有用结果、自愿继续和打扰程度；小样本不证明认知能力提升。
