# ReadFlow MVP PRD

文档修订 0.7 · 2026-10-25；软件版本 V0.4.1。本文确认数据库主库、双入口收藏、可选飞书互动、CSV 导出与外部 agent 分工。

## 1. 产品目标

把已经收藏的内容重新带回注意力中，降低开始阅读的门槛。后续通过有来源、贴合用户意图的 AI 反馈，解决疑问、检验理解或确定行动。收藏数量、摘要字数、消息送达都不能单独代表消化。

## 2. 职责与数据归属

| 部分 | 职责 |
| --- | --- |
| Chrome | 随手收藏标题／链接，选填标签与笔记，本机待同步队列、按状态筛选的收藏列表与状态操作 |
| ReadFlow 服务 | SQLite 唯一主库、鉴权、去重、任务、发送记录和导出 |
| 飞书私聊 | 可选链接入口、落库确认、阅读邀请与已读／稍后／跳过操作 |
| CSV | 用户主动下载的数据库内容快照，不含配对与任务状态 |
| 已有的对话型 agent（不限平台） | 后续承担正文理解、分析与追问；模型、凭证和费用由现有 agent 环境管理 |

SQLite 在现有服务单机私有目录运行，不新增数据库账号或托管平台。不提供飞书或其他在线表格同步。ReadFlow 不直接调用模型 API、不保存模型密钥。新增外部服务、费用、模型或托管方案须另行确认。

## 3. 已落地范围

- 两种入口共用数据库，按 URL 去重；新收藏不会覆盖已有状态和笔记。标签／笔记仅显式修改时更新；编辑 UUID 防止旧请求重放覆盖新值。
- 首次弹窗显示连接指引，可明确选择本机收藏；已配置后服务器暂时断网也能收藏。未入库内容显示“本机待同步”，不冒充备份成功。
- 普通用户只填 HTTPS 服务地址并配对，不再填写主库表格链接。扩展 ID、指纹、部署和发送排障归入配置／高级流程。
- 飞书事件先持久化，再由既有任务落库；落库后发送新增／已存在确认。失败保持可重试，送达不确定时保留请求 UUID。
- 阅读卡片提供打开、已读、稍后 24 小时、跳过；按钮验证用户、会话、已发送消息与记录绑定。状态写入数据库，Chrome 下次同步可见。打开原文不自动标已读。
- 每日提醒的时间、时区、语言和开关可配置；调度属于服务端。读取数据库，绝不依赖导出表。
- 手动 CSV 导出全部数据库记录，处理中文、换行、引号及表格公式注入；CSV 不等同完整数据库备份。

当前不抓文章正文、不下载或转写视频、不通过标题假装读过全文。飞书入口标题暂为 URL。未实现统一删除、独立笔记编辑器、多机部署、自动保留清理与完整 AI Review 界面。

## 4. 回顾与讨论 MVP

已实现独立 agent 配对、查询和确认后的引用回顾存储，首个接入目标为 Hermes；真实会话部署、Chrome 回顾界面及定时回顾仍待验证或实现。分析在用户已有的对话型 agent 中执行，不限定品牌、消息平台或宿主设备，也不要求与 Chrome 在同一台设备。ReadFlow 不调用模型 API，不保存模型密钥，不新建完整聊天窗口。

### 4.1 入口与职责

主要入口是用户已经使用的 agent 对话。用户直接发出回顾请求，无需先到插件点击“交给 AI”。插件中的“讨论这条”仅作为后续可选入口，用来指定素材，不是所有分析的前置步骤。

ReadFlow 提供经授权的资料查询和回顾记录追加能力；agent 查询证据、组织分析、与你讨论。飞书只是现有的可选收录／提醒渠道，其他对话渠道也可以承担展示与回复。消息送达不等于 agent 接收任务，更不等于分析完成。

首版优先接通一个用户实际使用的 agent，并验证输入渠道、身份认证、查询和保存能力。用户侧目标为一次连接授权，不添加模型选择、密钥或回调地址表单。具体连接协议在实现前确定，不宣称所有 agent 已自动兼容。

### 4.2 三种回顾

| 功能 | 如何触发 | 查询范围与依据 | 对话中展示什么 | 如何保存 |
| --- | --- | --- | --- | --- |
| 那年今日 | 用户说“看看那年今日”；可另行明确开启每日定时回顾 | 按用户时区，以收藏时间查找往年同月同日的记录，附当时笔记和当前状态；收藏日期不冒充阅读或笔记写作日期 | 展示少量旧素材、年份和来源，引用用户笔记；有近期相关记录时才比较，最后询问现在是否仍认同或仍想阅读 | 用户选定值得留下的讨论，预览后确认，追加一条关联旧素材与相关新素材的回顾记录 |
| 阅读习惯回顾 | 用户说“回顾最近一个月”；未指定范围默认最近 30 天并明确显示，可另行开启每周回顾 | 范围内的收藏时间、标签、当前已读／未读／跳过状态及用户笔记；说明实际记录数、缺失项与可用历史 | 先列计数和可核对的变化，再提出一两个可能的模式、反例和核实问题，不输出笼统人格画像 | 讨论后生成事实与解释分开的摘要，经用户确认追加保存，保留统计范围、依据与用户修正 |
| 盲区讨论 | 用户说“找出我可能忽略的证据”或“你的总结是否美化了我”；未指定主题时先让用户选定问题，不默认扫描全部隐私记录 | 围绕问题查询用户笔记、相关收藏及可访问的原文／摘录，主动寻找不支持当前判断的记录 | 提出一个可检验的疑问，列支持证据、反例、其他解释和信息缺口；允许用户反驳，不把推测写成事实 | 展示包含用户反驳或修正的最终摘要，确认后追加保存；仍有分歧时标注“未确认假设” |

“那年今日”没有命中时如实说明，可询问是否改为附近日期或随机回顾，不把替代结果冒充当天记录。阅读习惯的状态统计只代表查询时的数据库状态；现在记录服务端标记已读时间及后续状态变更，但旧记录的时间未知；可以统计有记录范围内的“标记已读篇数”，必须说明覆盖范围并按素材去重，不能称为实际读完量、阅读耗时或真实行动量。

定时触发须由用户单独开启，明确功能、频率、时区、接收对话及暂停方式；由已有 agent 的可用调度能力执行。同一周期不重复推送，没有回应不追加催促。若 agent 不支持调度，则保留手动触发，不偷偷新增服务。现有 ReadFlow 每日未读提醒与这些回顾任务是不同功能，不能共用一个含糊开关。

### 4.3 结果展示与讨论

第一份结果显示在 agent 对话中，按“依据 → 解释 → 反例与不足 → 一个问题”组织，可展开或打开引用。用户在同一会话继续追问、反驳、补充经历；不强迫回插件完成讨论。

ReadFlow 收藏页继续作为首页。后续新增轻量“回顾记录”入口，展示已确认保存的回顾及其日期、类型和关联素材；单条素材可查看关联回顾。它是持久化结果的查看处，不复制完整聊天产品。

未保存的讨论只停留在既有 agent 对话及其自身存储中，不暗示已经进入 ReadFlow。ReadFlow 不默认导入完整聊天历史，也不自动建立人格档案。

### 4.4 确认保存流程

1. agent 生成分析并继续讨论，此时仅为草稿。
2. 用户说“保存这次回顾”或使用等价操作。agent 展示准备保存的摘要、引用和用户修正，明确保存的是哪一版。
3. 用户确认具体内容后，agent 通过授权能力追加回顾记录。仅确认接收定时消息或继续聊天，不视为同意保存。
4. ReadFlow 成功落库后返回记录 ID，agent 才显示“已保存”，并提供可返回查看的入口。失败显示“尚未保存”并保留草稿；结果不确定时用同一请求标识查询或重试，避免重复记录。
5. 用户之后修改结论时追加修订并关联原记录，不静默改写历史。可以保留“有分歧／未确认”的推断，不能将保存动作解释为用户认同全部内容。

回顾记录最少包含：类型、标题、查询时间范围及用户时区、生成／确认／保存时间、agent 来源、关联素材 ID、可核对的引用或必要摘录、观察事实、推断与反例、用户反馈、确认保存的摘要、幂等请求标识。必要摘录用于保留当时依据，不默认复制整篇文章或全部对话。引用失效或素材发生变化时应标注，不能伪装成当前原文。

保存回顾不覆盖素材原始笔记、不改变已读／未读／跳过状态，也不代表用户已经采取行动。先只给 agent“查询已授权资料”和“追加已确认回顾”两类能力，不授予删除素材、覆盖原笔记或任意修改配置的权限。长期连接授权不能替代每次回顾内容的保存确认。

## 5. 基于证据的真实反馈

### 5.1 输出约束

- **不美化，也不刻意贬低。** 不以“你很有洞察力”“你正在成为更好的自己”等无证据评价填充结果；不为显得尖锐而制造缺点。温和或尖锐都不能代替证据。
- **事实与推断分开。** 引用用户原话时注明来源和日期；作者观点、用户笔记、agent 推断分别标识。每个具体观察要能追溯到记录，跨多条记录的模式要列出范围与依据。
- **主动检查反例。** 支持某个解释的同时，检查授权范围内不支持它的记录，给出其他合理解释。没有找到反例不等于不存在；说明检索范围，不声称全面了解用户。
- **尊重信息缺口。** 收藏不等于认同，已读不等于理解，跳过不等于反对，没写笔记不等于没行动。只有标题和链接时只能讨论收藏记录，不能假装读过正文。
- **不把局部行为变成人格定论。** 不根据收藏清单给用户诊断心理问题、贴人格标签或断言动机；提出可验证的问题，允许回答“不是这样”。
- **接受纠正。** 用户补充与原判断冲突的信息时，说明哪些观察仍成立、哪些解释需撤回或保留为分歧。不得把用户反驳解释成“这正说明你有这个盲区”，形成不可反驳的论证。
- **不承诺发现盲区。** 证据不足时可以只返回“目前无法判断”及一个补充问题，不为了每次交付而生成洞察。

### 5.2 对照示例

以下数字仅为说明输出方式的虚构例子，不代表任何真实用户记录。

不合格：“你收藏很多效率文章，说明你很有成长意识，但也在逃避行动。”

合格：“最近 30 天有 12 条效率主题收藏，当前 9 条仍标为未读［素材引用］。这可能是集中储备，也可能是重复寻找方法；其中一条笔记提到已尝试某种方法［笔记引用］，不支持简单判断为‘没有行动’。ReadFlow 没有你的实际执行记录。你愿意说说最近用过哪一种方法吗？”

盲区讨论的目标是帮助用户修订判断，而不是让用户被赞美、被震撼或接受 agent 的画像。

## 6. 验收

### 6.1 已有基础能力

- 不配置飞书凭证也能完成数据库收藏、状态修改和 CSV。
- 收藏页为默认首页，未读／已读／跳过筛选数量与状态一致；桌面列表展示标题、来源／时间、标签、笔记摘要及状态操作，窄屏换行。
- 重复收藏、重启与响应丢失不会产生重复记录或重复应用旧编辑。
- 不暴露在线表格同步入口、写表导出接口或建表脚本，CSV 不依赖飞书授权。
- 卡片伪造、越权用户、未知消息与重复事件不错误改变阅读状态。
- 服务故障保留本机待同步内容；文档区分模拟测试和真实部署验证。

### 6.2 回顾能力上线前验收

| 场景 | 必须满足 |
| --- | --- |
| 在 agent 对话直接发起三种请求 | 无需先打开插件；明确类型、范围和可用依据，结果显示在当前对话 |
| 那年今日无记录或不足一年 | 明确无匹配；不捏造历史，不默认更改日期范围 |
| 只有链接或标题，没有正文和个人笔记 | 不生成正文摘要、用户动机或人格判断；提示补充材料 |
| 阅读状态缺少变更时间 | 只报告当前状态分布，不计算不存在的阅读速度或期间完成量 |
| 询问“你是否美化了我” | 回查证据、提供反例或替代解释，撤回无依据赞美，不改用无依据批评 |
| 用户反驳分析 | 保留原始事实并修订解释；允许分歧，保存摘要必须包含相关用户修正 |
| 未确认保存或用户拒绝保存 | ReadFlow 不新增回顾记录，不改变原笔记和阅读状态 |
| 确认后写入失败或响应丢失 | 不报告假成功；保留草稿，同一请求重试最多形成一条记录 |
| 成功保存多素材回顾 | 可从回顾入口和关联素材查看同一记录，能核对依据和确认内容 |
| 定时任务未开启、已暂停或无回复 | 不主动执行未授权调度、不继续催促；现有未读提醒与回顾订阅分别控制 |
| agent 未连接或能力不足 | 明确不可用，保留手动导出资料方式，不声称已自动移交或自动回写 |

## 7. MVP 范围与验证方式

先完成一个实际 agent 的“查询资料 → 有引用的回顾 → 对话核实 → 确认后追加保存”闭环，再验证其他平台和定时能力。暂不做通用 agent 平台、完整聊天镜像、人格评分、自动抓取全网正文或自动覆盖用户笔记。

试用观察重点是：用户是否能核对引用，是否纠正了错误解释，是否获得一个具体有用的问题或判断修订，以及是否愿意再次使用。保存次数、赞美程度、回复长度与所谓人格准确率不作为成功标准。可用小规模试用检验流程，不据此宣称提升认知能力。

本轮已实现 agent 独立配对授权、有限查询、带引用确认回顾的幂等追加与历史查询，并提供 Hermes 可调用的 HTTP 签名工具。确认由已授权 agent 如实转述；ReadFlow 无法独立核实外部聊天用户身份。结果先在 agent 对话展示，可按回顾／素材 ID 取回；Chrome 回顾列表与定时 AI 回顾暂未实现。验证使用本机签名请求与 SQLite，真实 Hermes 部署尚未验证。详见 [agent 接入指南](AGENT.md)。

### 已读时间规则

readAt 为当前已读状态的标记时间（服务端毫秒），不是收藏时间或实际阅读完成时间。重复标记不更新；未读／跳过清空当前值，历史事件保留，再次已读记录新时间。旧资料、本机导入或其他缺失时间不得补造。Chrome 同步和 CSV 可取得该字段，查询可以按 readAt 筛选。期间统计需区分当前已读分布、发生过的状态事件与按素材去重的标记数量。
